# AI 对话记录 02 · 架构与资源约束建模

## 阶段
确定技术架构、资源约束口径、章节划分。

## 人类指令（要点）
- 用最朴素的方式实现，不要复杂框架；既要能演示，又要经得起评委看代码。
- 资源约束必须明确、可调、可验证。

## AI 的方案
### 技术架构
- 原生 HTML + CSS + ES Module，hash 路由，零构建、零运行时依赖。
- 模块化划分：`bit`（位工具）、`huffman`、`phrasebook`（词典与场景）、`protocol`（编码）、`network`（信道模拟）、`energy`（能量）、`bench`（基准）、`ui/*`（章节视图）。
- Service Worker 预缓存全部外壳，PWA 可安装、可离线。

### 资源约束（最终口径）
| 约束 | 取值 |
|---|---|
| 主约束：极端窄带 | 100–2400 bps 可调；丢包 0–50%；RTT 100–2500 ms；包载荷 16–128 B；默认 600 bps / 30% / 1.5 s / 32 B |
| 主约束：能量 | 1% ≈ 410 J（3.8 V × 3000 mAh），无线电 0.8 W、屏幕 0.4 W、CPU 0.3 W |
| 次约束 | 旧设备算力（编解码耗时实测）、离线可用（SW 缓存清单） |

### 八章结构
开机自检 → 序章 → 绝境终端 → 编码实验室 → 弱网实验室 → 实测基准 → 离线与自足 → 终章。

## 讨论中的取舍
- **是否引入第三方图表库**：否。柱状图/时间轴/Huffman 树均用 SVG 手写，避免几百 KB 的依赖，也符合主题。
- **是否在线训练 Huffman**：否。离线训练静态模型预装，运行时零流量；同时把“动态方案及其表头成本”也实现出来做诚实对照。
